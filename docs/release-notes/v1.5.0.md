## New features

* **Agent profiles.** **Settings › Agent profiles** keeps a set of accounts (used from the top, the next one taking
  over at a limit), the MCP servers to leave out, and a permission choice (follow the app setting, run with permission
  checks, or run without) under one name. Pick a profile when you start a session, create a Job or add a Task.
  Resuming a conversation from History remembers the profile it ran as and says so in the dialog.
  `astera agent-profiles` and the MCP tools do the same from a terminal or an agent, and the SDK reads profiles.
* **Observe: a record of what agents did.** In **Settings › Security & Access**, the switch **Record agent tool
  calls** is Off until you turn it on. With Observe on, sessions Astera starts afterwards have their tool calls
  recorded as a kind of action and a short target, never the full command, its output or a file's contents. **Audit
  Logs** lists them by day, and **Policies** holds the Rules that say what each call would have got. Nothing is
  blocked in this mode. Records are kept 30 days. A table shows what can be seen for each agent and kind of session.
  `astera audit` and `astera policies` read the same data with the app closed.
* **Token totals in Run detail.** A Run and each of its Tasks now show the tokens their sessions used, read from what
  Claude and Codex write, and a link from Run detail opens Audit Logs on that Run's calls.
* **Enforce: stop what the Rules deny.** Choose **Enforce** in the same switch and Claude Code and Codex sessions
  started afterwards run a check before each tool call. A call the Rules deny does not run, the agent is told it was
  blocked, and the call shows in Audit Logs as blocked. Astera's own settings folder is always protected. Turning it on
  shows what the last 7 days of calls would have hit. It adds about 0.1 seconds to each tool call. It needs Claude Code
  2.1.306 or later and Codex 0.160.0 or later; a session that cannot be protected does not start. An agent running as
  you can still change the settings files from a script it runs.
* **Credentials list.** **Settings › Security & Access › Credentials** lists what Astera keeps out of agent sessions:
  shared MCP servers' stored keys appear on their own, and you can add environment variables and CLI logins (gh, AWS
  CLI, Google Cloud CLI, npm, Docker, kubectl), for every session or only chosen projects. Sessions started afterwards
  do not get them, and Audit Logs shows when Astera's own GitHub and MCP Gateway calls used one. `astera credentials`
  shows the list and says what hiding does not reach: your OS login stores and files a program running as you can
  read.
* **Sandboxed sessions.** An agent profile has a switch, **Run in the sandbox**, off by default. Turned on, its
  terminal and chat sessions start in Codex's or Claude Code's own sandbox. Writes stay in the work and temp folders,
  and the folders holding logins and the OS secret store cannot be read. The network still works. Claude Code has no
  sandbox on Windows: there only its file tools are kept from the login folders, and the shell is not restricted. A
  sandboxed session cannot hand work to sessions, Jobs or Tasks outside the sandbox, cannot call the Host directly,
  and its tab carries a marker. Codex needs 0.160.0 or later, and on Windows each Codex account needs a one-time
  **Set up**, which shows Windows' administrator prompt. **What the sandbox blocks**, in Security & Access, lists what
  it covers for each agent and system.
* **The tab bar scrolls.** Tabs shrink until half of a name shows, then the bar scrolls, by mouse wheel too.

## Fixes

* **Closing an app an agent checked ends what it started.** An app an agent launched in the **Agent app workspace**
  could leave a program it had started in the background running after it was closed, such as a development build of
  Astera leaving its own Host. On Windows the app now runs in a job of its own, and everything in the job ends with
  it. On Linux and macOS Astera now also finds and ends what the app started in the background, as long as the
  program that started it is still running when the app is closed.
* **A Codex session keeps its own conversation.** A Codex session that had not been used yet could take the
  conversation file of another Codex running in the same folder, whether in Astera or outside it, and show that one's
  usage and turns. A session now takes a file only when its own Codex has it open. Where the system cannot tell which
  program holds a file, the old rule applies.
* **Closing a Windows terminal no longer risks ending the wrong process.** When the console list did not answer, the
  shell's process id was ended even if it had been reused. It is left alone now.
* **Text sent to a session is no longer lost to an early Enter.** Sending to a session from the CLI, the browser pane
  or Slack, and a roll's carry-on prompt, now press Enter only once the session has drawn the text and gone quiet.
  Before, Codex could take the Enter for part of the paste.
* **Removing a worktree works after a sandboxed session wrote read-only files in it.**
