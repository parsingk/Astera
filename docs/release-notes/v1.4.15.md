## New features

* **Jobs that carry their work through GitHub.** Tick **Carry it through GitHub** when you make a Job, or pass
  `--github-lifecycle` to `astera jobs create`. Once every Task of a Run is done, Astera pushes the Run's branch, opens
  a draft pull request or binds the open one, and waits for GitHub CI on the commit it pushed. A Job made from a GitHub
  issue links its pull request to the issue. Astera never merges: it tells you when the pull request is ready, and you
  merge it.
* **CI failures are repaired or rerun, by what caused them.** When CI fails, Astera reads the failed job's log and
  names the kind of failure: a test, the build, lint, type checking, or something outside the code such as the network
  or the runner. A failure in the code goes back to an agent with the log, in the Run's own branch, and its fix is
  pushed and checked again. A failure outside the code is rerun instead, as many times as **Settings › GitHub**
  allows. When Astera cannot decide (no CI ran, CI took too long, someone else pushed to the branch, the pull request
  was closed), it asks you.
* **Merge-ready, and withdrawn when it stops being true.** After CI passes, a second agent reviews the whole pull
  request, including whether the change weakened the CI. When the review passes, the Run is **merge-ready** for the
  commit it reviewed. A new push, a failing check, a new base or a closed pull request withdraws it, and
  `astera runs reconverge` carries the Run through again.
* **Where you see it.** A Run's detail has a GitHub section with the pull request, its checks, where Astera stands, the
  repairs made, Astera's review and GitHub's own, and when merge-ready was decided. Each step is on the Run's timeline,
  the Job card says when the Run waits for CI, repairs it or is merge-ready, and How It Works records what GitHub said.
  The Astera Host carries on with the app closed and after a restart, on this computer or on a Remote Runtime. The CLI,
  the MCP tools and `@astera-app/client` 0.4.0 read and answer all of it.
  [docs/jobs.md](https://github.com/parsingk/Astera/blob/main/docs/jobs.md) is the guide.
* **A session an agent started closes its tab when it ends.** The sessions an orchestration, a Job's workers or its
  reviewers open no longer pile up as tabs after they finish. A session you open yourself keeps its tab as before.
* **The AppImage describes itself.** AppImage catalogs now show Astera's summary, its description and a screenshot.

## Fixes

* **On Linux, plugin secrets work where new folders are group-writable.** Under `umask 002`, the default on some
  distributions, the plugin secret store refused to open. It now removes group and other write from its own folders
  inside the profile, and still refuses anything else.
* **On Linux and macOS, a reattached Claude pane draws at once.** After a tab reattached to a running session, the pane
  stayed blank until the window was resized. The program now draws again as soon as the tab is back.
* **Account Rolling types continue only after a limit it detected is lifted.** It no longer sends `continue` on a
  guess from a usage figure or an old block record. A limit read off a usage figure alone is shown and not acted on.
* **A Run's detail closes when you leave the Jobs view.** It used to stay open with nothing in it.
* **How It Works names a Job made from a ticket by the ticket.** It showed the ticket's quoted content as the request.
  It now shows the sentence that names the ticket, and the record header keeps its buttons whole in a narrow pane.
