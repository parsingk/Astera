## New features

* **Share Claude Code plugins with every account.** **Settings › MCP & Skills** has a **Plugins** group. Choose **Add**,
  pick a Claude account, and its plugins are listed with its servers and skills; pick the ones to share. Astera installs
  one copy of each in its own folder, and every Claude session Astera starts loads that copy, so every account runs the
  same version. While a shared plugin is on, it replaces an account's own copy of the same name in those sessions; turn
  it off or remove it and the account's own copy runs again from its next session. Nothing in a Claude account's folder
  is changed, and a `claude` you start outside Astera does not get the shared plugins. A plugin that needs settings
  values, comes from a marketplace address that holds a password or key, or was not installed from a marketplace is
  shown with the reason it cannot be shared. The slash menu lists the shared plugins in place of the copies they
  replace, and `astera ext list` names them.
* **Shared plugins reach Codex accounts too.** Every shared plugin is also installed into every Codex account, so a
  `codex` you start outside Astera has it as well. Astera puts it into each account in Codex's form: agents are left
  out, commands become skills named `<plugin>:source-command-<name>`, and Astera trusts the plugin's hooks, so no hook
  review menu stops a session. A Codex account's own plugin of the same name is turned off while the shared one is on,
  and turned back on afterwards if Astera turned it off. An account with a running Astera Codex session gets a new
  plugin or version, or loses a removed one, once its sessions end; turning a plugin on or off reaches it at once. A
  plugin's row shows each Codex account's state, and the Codex `@` menu lists the skills of the plugins Codex has
  enabled.
* **Plugin updates only when you say so.** Astera looks for newer versions when it starts and once a day, and **Check
  now** looks at once. A newer version only marks the row **Update available**: a shared plugin never changes until you
  press **Update**. If a marketplace asks to run a command of its own to install or update a plugin, Astera shows you
  the command and runs it only after you confirm.
* **Importing settings keeps each account's plugin choices.** Once any plugin is shared, **Import settings from the
  default account** keeps a Claude account's own `enabledPlugins` and `extraKnownMarketplaces`, and a Codex account's
  own `plugins` and `marketplaces` tables in `config.toml`, instead of copying the default account's.

## Fixes

* **The register list is easier to read, and long lists keep their buttons.** In **Settings › MCP & Skills › Add**, an
  account's MCP servers, skills and plugins sit in areas under their names, with a line between areas, instead of a
  kind word on every row. A confirmation dialog now stops at 80% of the window and scrolls its list inside, so a long
  list no longer pushes the buttons off the screen.
* **A Codex settings import keeps a linked `config.toml` a link.** Importing settings into a Codex account whose
  `config.toml` links elsewhere now changes the file the link points to, as writing a folder's trust already did.
* **Japanese text spells フォルダー and ブラウザー one way throughout.**
