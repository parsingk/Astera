## New features

* **See what runs in your Kubernetes cluster.** When kubectl is found, a Kubernetes icon sits above the terminal icon on
  the left rail. It opens the bottom panel's **Kubernetes** tab: pick the cluster (a kubeconfig context) and the
  namespace, or all namespaces, and browse the resources by kind. Each kind shows how many there are and a red dot when
  something needs attention, such as a Pod in CrashLoopBackOff or a Deployment short of ready replicas. The table shows
  the columns `kubectl get` shows, and the detail column has a summary, the live YAML, events, `kubectl describe` and a
  workload's Pods. Drag the detail column's left edge to resize it. Everything follows the cluster while you look at
  it and stops when you look elsewhere. A Secret's values stay hidden until you press **Show values**. **Open in
  editor** shows an object's live YAML in an editor tab. Choosing a cluster or a namespace never changes your
  kubeconfig. The **Operation log** moved into this tab.
* **Pod logs.** Right-click a Pod and choose **Logs** or **Previous logs** (the container before its last restart, on
  by default for a Pod in CrashLoopBackOff). The logs open in a tab of their own in the bottom panel, with a container
  picker (init containers and sidecars marked), follow, a filter, time stamps, line wrap, **Save** and **Clear**. They
  keep coming while the panel is folded, and a line says how the container exited when the stream ends.
* **Edit, delete, restart and scale from the cluster view.** Press the pencil in an object's editor tab to edit its
  YAML, then **Apply…**. Every change opens a confirmation that runs a server dry run and shows the cluster now against
  the result, with one button that names the cluster. If only the cluster's own status changed in the meantime, the
  edit goes through; if something else changed, Astera says so and compares again. A Secret can be edited after
  **Show values**, and its values stay hidden in the comparison. **Delete…** works for every kind and lists what goes
  with it: a Deployment's ReplicaSets and Pods, a Namespace's contents, a CRD's resources, a StatefulSet's volume claims
  it keeps. Deleting a Namespace or a CRD asks you to type its name. Deployments, StatefulSets and DaemonSets can be
  restarted, and Deployments and StatefulSets scaled. An editor tab offers **Compare with project file** when exactly
  one manifest in the project declares the object and targets the same cluster. Results go to the Operation log.
* **A shell into a container.** Right-click a running Pod and choose **Shell** (with a container picker when several
  run). A **Shell** tab opens in the bottom panel with bash, or sh when the container has no bash. Copy, paste, find
  and clear work as in a terminal; pasting copied files does nothing there, since a path on your computer means nothing
  in the container. When the shell ends, the tab says so with its exit code and stays until you close it. Closing a tab
  whose shell still runs ends kubectl, but Kubernetes keeps that shell running inside the container; type `exit` first
  to end it.
* **Port forwarding.** Choose **Port forward…** on a Pod, Service or Deployment, pick the remote port, and the local
  port (the same number when it is free), and Astera forwards it on 127.0.0.1 only. The **Port forwarding** list in the
  Kubernetes tab shows each forward's state and how long it has run; click the address to open it. When a forward ends
  it says why (the Pod was replaced, the Pod refused the connection, or the connection was lost) and offers
  **Reconnect**; nothing reconnects by itself. kubectl notices a replaced Pod only on the next request. **Stop all**
  stops every forward, and quitting Astera stops them all.
* **Copied files paste as paths in terminals.** Files copied in Explorer, Finder or Astera's explorer and pasted with
  Ctrl+V (Cmd+V on macOS) into a session tab or the bottom panel's terminal type their paths on one line, a path with
  spaces in double quotes. Pasted anywhere else, the copy pastes as before.

## Fixes

* **Ctrl+C copies in the bottom panel's terminal.** With text selected, Ctrl+C sent an interrupt to the shell instead
  of copying. It now copies, as the other terminals do; with nothing selected it still interrupts.
* **Dropdowns match the theme.** The Kubernetes manifest toolbar, the Higgsfield workspace picker and the Job source
  picker opened a list in the operating system's style. They now use Astera's own dropdown.
* **A local address opens without a project.** Clicking a `localhost` or `127.0.0.1` link with no project open did
  nothing, because such links open in a preview tab and a preview tab belongs to a project. They now open in your
  browser in that case.
* **A new bottom tab scrolls into view.** With many tabs in the bottom panel, a newly opened tab could sit past the
  edge of the tab strip. The strip now scrolls to the tab that is shown.
