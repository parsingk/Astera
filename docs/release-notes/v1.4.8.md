## New features

* **Codex sessions know what Astera offers too.** A Codex session Astera starts is now told, as it starts,
  which of Astera's features are turned on, the way Claude sessions already are. If your Codex account sets
  its own `developer_instructions`, Astera leaves them alone and sends nothing.

## Fixes

* **Codex workers no longer stop at the update notice.** When a new Codex version was out, every Codex
  session Astera started opened on Codex's "Update available" menu, and a worker or coordinator with nobody
  in front of it stopped there. Astera now starts Codex sessions with the update check off; Codex run outside
  Astera still tells you about updates.
* **Codex workers no longer stop at the folder trust menu when a path uses forward slashes.** Astera marks a
  worker's folder as trusted for Codex before the worker starts, but a Run created with a path like
  `C:/repo` (which the CLI and MCP accept) was recorded in a form Codex on Windows does not read, so the
  worker stopped at "Trust this folder?". Astera now records it the way Codex reads it, and corrects the
  entries it wrote before.
