## New features

* **Other agents can drive Astera through MCP.** `astera mcp serve` is an MCP server for Claude Code,
  Codex, Cursor and any other MCP client: list projects, create and run Jobs, lay out Tasks, follow a
  Run until it needs you (`wait_for_run`), answer its questions, stop and resume it, and read each
  Task's checks and output. What a client may do is set in Settings > CLI (off, read only, or read and
  control); everything it does is written to the journal under the client's name. See `docs/mcp.md`.
* **Register Astera with Claude Code and Codex from Settings.** Settings > CLI shows the line to add
  Astera to each client on this computer, and a Register button runs it for Claude Code and Codex.
* **Sessions, GitHub and How It Works over MCP, each behind its own setting.** With the session setting
  on, a client can list Astera's sessions, read them and send them messages. With the GitHub setting
  on, it can open a pull request (a draft unless asked otherwise), re-run failed CI and turn an issue
  written by a repository member into a Job; reading PR and CI status needs no setting. How It Works
  records can be listed, read and written again.
* **MCP over HTTP for agents on your other devices.** Turn on Settings > CLI > MCP over HTTP and a
  client on another computer can use this Astera with a token. It listens only on this computer until
  you also allow other devices on the network, and Settings lists the addresses they can use (local
  network and Tailscale). Use it on a private network: the connection is not encrypted.
* **A Job with no Tasks gets planned.** Its coordinator lays out the Tasks itself, and the workers do
  the work. Stopping a Run now stops its coordinator too, and resuming starts a new one.
* **The Host keeps How It Works going while Astera is closed.** It detects the work in your sessions
  and writes the records itself, so nothing waits for the app to be opened.

## Fixes

* **How It Works counts the right files.** Work an agent edited and committed in one go is recorded
  instead of being dropped as "nothing changed". Files that came in through a `git pull`, or through
  Astera's own Job merge, are no longer counted as the session's work, for Codex sessions too.
* **Codex goals open and close their task on codex 0.160.** A finished `/goal` closes its task by
  itself again, and a second goal is no longer missed after Codex starts a sub-agent.
* **A Codex sub-agent no longer shows up in History as its own session,** where it could take the
  place of the conversation it belonged to. Deleting a project's history deletes it too.
* **A Run's write-up reads the folder the work was done in,** so it no longer asks for review because
  it looked at the project before the merge.
* **Stopping a Run no longer brings the background Host down.**
* **A Job with a long objective starts.** Its worktree and branch names are shortened; they used to
  exceed the Windows path limit.
* **A finished Run's coordinator and idle workers close by themselves** ten minutes after the Run ends
  or after your last input, whichever is later.
* **The merge button in a Job's detail window merges.** It used to fail with "unknown run".
* **`astera host start` no longer locks the installation folder,** which could block the next update.
* **`astera` stays reachable from new Windows terminals when your user Path is long.**
