## New features

* **Add MCP servers, skills, commands and agents once, for every account.** **Settings › MCP & Skills** has an
  **Add** button: pick an account, tick what it holds, and every account's sessions get it from then on, Claude
  and Codex alike, rolled sessions included. Skills, commands and agents are copied into each account and kept in step:
  a copy removed by hand is put back, one edited by hand is put back with your edit kept aside, and an account that
  already has its own different copy is left alone and marked, with a button to replace it. An MCP server's
  environment values move into a store only you can read and reach a session only when it starts; the screen and the
  CLI show their names, never a value. Each item can be turned off or removed. `astera ext list` and `astera ext sync`
  do the same from a terminal, with no app open.
* **One MCP server per project folder, not one per session.** A shared MCP server that runs as a local program now
  runs once for each project folder, and every session opened in that folder uses it, so five sessions no longer start
  five copies. It stops after five idle minutes and restarts by itself if it dies. Where sessions must not share one,
  as with a browser server where one session's page would overwrite another's, tick **Run per session** on that
  server. Browser servers such as playwright and chrome-devtools start out that way, each session with its own
  browser profile.
* **Provider settings are changed in place.** When Astera writes to a provider's settings, Codex's `config.toml`
  included, it changes only its own entries and keeps your comments and the keys it does not know.

## Fixes

* **Copying the default account's settings no longer replaces a Codex account's config.** It merges into the
  account's `config.toml` instead, and once anything is registered in **Settings › MCP & Skills**, it leaves MCP
  servers, skills, commands and agents to that screen rather than copying them a second time.
