## Fixes

* **Installing an update no longer fails with "Astera cannot be closed".** Astera keeps a Host process
  running so that sessions survive the app closing, and on Windows that process is the very file an
  installer has to replace. The installer already ended it — but the app started a new one a second
  later, which is what it does whenever it loses one, so whether an install got through came down to
  which of the two moved first. The installer now waits the app out, and the app stands its Host down
  before handing over.
* **On Windows, the update confirmation no longer says running sessions keep going.** They cannot: the
  Host has to end for the new version to be written. macOS and Linux are unaffected — a running
  binary can be replaced there, and sessions carry on through an install as before.
