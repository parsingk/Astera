## New features

* **A web page tab shows the dev server's page beside the session that is editing it.** A browser tab
  is a pane tab like a session or a file, so it sits side by side, splits and drags like one. Its
  toolbar has back, forward and reload, an address bar, DevTools and open-in-browser, and
  right-clicking inspects an element. Viewport presets from Mobile S to Desktop emulate the size, the
  device pixel ratio and a phone's own handling of a viewport meta tag, and rotate. Self-signed
  certificates are allowed for `localhost` only, and so are permission prompts such as camera and
  notifications.
* **A `localhost` address clicked in a terminal or in the run console opens in a web page tab.**
  Anything else opens in your browser, and `Ctrl`/`Cmd`-click inverts it. A run configuration can
  also carry a **Preview URL**, and that tab opens, or refreshes, whenever the configuration starts,
  waiting for the server to come up. Without one, the run's own tab notices the first `localhost`
  address the run prints, offers it once and keeps a button for afterwards.
* **Design Mode picks elements on that page and collects them as notes.** Turn it on in the tab's
  toolbar: hovering highlights an element, clicking pins a numbered bubble to it and opens a comment
  box where you clicked, and you answer "What should change?" and mark the intent **Change** or
  **Question**. Up to twenty notes per tab, listed in a card over the page, and numbers are never
  reassigned. The mode turns itself off when the page navigates away.
* **A batch of notes goes into a session as one markdown block.** **Send to session** pastes it and
  submits it, and refuses a session that is waiting on a question rather than feeding the text to a
  dialog. The batch stays in the card, to be sent again once you have answered. Each note carries the
  element's selector, position, styles and HTML, its nearby text with secrets redacted, and the path
  of a screenshot cropped to that element, so the agent looks at the element instead of reading a
  description of it. **Copy** puts the same block on the clipboard.
* **The session's agent gets a web page tab of its own and drives it.** It opens a page on this
  project's dev server, reloads it after a change, reads the address and the title, and reads back
  what the console and the network reported since that load; it also reads the page as text, looks at
  it as an image, clicks elements, fills values, presses keys and waits. "Does the page still render,
  and is the console clean" becomes something the agent answers by looking instead of something it
  asks you to check. The tab is a real tab you can watch, marked as the agent's and shown busy while
  a script runs, with a Stop in its context menu. It takes addresses on this machine only, so a
  link, or a redirect from the dev server, that would leave is refused. Off by default: turn on
  **Agent browser (experimental)** in settings and it installs the `astera-browser` skill into your
  accounts, for sessions opened afterwards.
* **A project can have several runs going at once.**
* **The run console links what it prints, and can be searched.** A file path in the output opens that
  file in the editor at that line, for Node, TypeScript, JVM and Python frame shapes, and a URL opens
  in your browser. `Ctrl`/`Cmd`+`F` finds text in the output instead of sending `^F` to the process. A
  tool rail beside the console reruns, stops, scrolls to the end, clears and finds, and the strip's
  right end shows the selected run's command and how long it has been going, or took.
* **The Run Configurations dialog holds a draft until you press Apply.** Every edit, addition,
  removal and duplicate goes to the draft; Apply commits the whole list in one call and names every
  configuration it refuses, and Cancel, Esc and the backdrop ask before discarding. The tree gained a
  search box and a marker per row for what is not applied yet, what has a required field left empty
  and what the last Apply refused. Environment variables are a Key/Value table instead of a box of
  `KEY=VALUE` lines, and pasting a block of those expands into rows.
* **Run configurations can be filed into folders.** A folder crosses tool kinds, so a Frontend folder
  holds an npm script beside a Gradle task, and the dialog's tree and the toolbar's configuration menu
  both group by folder first. A folder exists as long as a configuration names it: the tree's button
  files the selection into a new one and names it inline, arrows reorder within a group, and
  double-clicking a folder renames it. A project that never makes one sees what it saw before.
* **One ▶ can start a chain of runs.** A configuration can name others, and the new **Compound**
  kind has no command of its own. Its members start together, and one stop button stops every one of
  them. Each step keeps its own working directory and environment, and every command is assembled
  before the first step starts. So a required field left empty three steps down refuses the press
  with nothing running. A chain that loops, or that names a configuration which is not there, is
  refused.
* **A file in the tree can be run from its context menu.** `.py` (a `test_*.py` as pytest), `.js`,
  `.mjs`, `.cjs`, a Docker Compose file and a `.csproj`/`.fsproj`/`.sln` offer to run; a filename that
  cannot say how to run itself gets no menu item rather than one that would refuse when pressed. The
  run leaves a temporary configuration behind, five per project, and editing one makes it permanent.
  The title bar's configuration widget is now a pill that says how many runs are up and opens a menu
  of the project's configurations, the recently run ones first, and `Shift`+`F10`, `Ctrl`+`F2`,
  `Ctrl`+`F5` and `Alt`+`Shift`+`F10` run, stop, rerun and pick one without clicking out of the
  terminal first.
* **Codex accounts show how much of their limit is used.** The two bars, the 5-hour window on top and
  weekly underneath, were drawn for Claude accounts only. They are on the account rows and in
  Settings → Accounts for Codex accounts too now.
* **A job's dependency graph is drawn as cards, layer bands and arrows.** A task is a card in its
  status colour with the status glyph beside it and a second line for an open gate's question, or for
  the provider running it. Tasks in the same layer sit inside a dashed band, a dependency arrives
  under an arrowhead so its direction is visible, and clicking a task fades everything its dependency
  chain does not reach. A sibling that merely waits on the same thing fades with the rest.
* **Every code block in the markdown preview has a copy button.** It sits at the block's top-left and
  puts the block's text on the clipboard.

## Fixes

* **`Ctrl`/`Cmd`+`C` in the run console copies the selection instead of interrupting the run.**
  Dragging over a stack trace and pressing it copied nothing and sent an interrupt to the server that
  had printed the trace. With no selection the key still reaches the process.
* **`/astera-orchestration` and `/astera-task` work on Codex on Windows.** Both skills began by
  reading `$ASTERA_CLI`, which is an unrelated and empty variable in the PowerShell Codex runs there,
  so the skill decided the session had not been started by Astera and told the agent to stop.
* **Double-clicking the run widget in the title bar no longer resizes the window.** The title bar
  toggles maximize on a double-click and the widget sits inside it, so double-clicking a
  configuration name or ▶ un-maximized the window out from under you.
* **A git command the OS refuses for a moment is tried again.** On Windows, under heavy parallel
  spawning, the process is occasionally refused before git runs at all, and the app read that as the
  command having failed, so a merge, a pull request or a branch read that had nothing wrong with it
  failed with it.
  Nothing was started, so one retry is safe.
* **Settings opens on General.** The modal opened on Info, which reports the version and the account
  count and changes nothing. Info now sits last in the list.
